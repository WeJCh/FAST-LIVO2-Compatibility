# FAST-LIVO2 3 公里级回环检测与全局建图优化方案

## 1. 当前结论

FAST-LIVOSAM 的**激光回环检测与全局优化后端**已迁移至主项目 FAST-LIVO2，并已在机器狗 `session_20260722` 的公里级首尾回环数据上完成验证。

验证结果：

- 共保存并优化 `461` 个关键帧；
- 成功接受 `24` 条回环约束；
- 首尾道路、建筑立面原有的分层和错位基本消失；
- 已导出彩色稠密的全局优化点云，肉眼检查首尾区域对齐良好。

因此，当前的**激光回环迁移工作已经完成**。现阶段回环不是视觉回环：相机用于 FAST-LIVO2 的 VIO 前端和 RGB 着色，回环候选与几何约束仍来自 LiDAR 点云。

## 2. 当前模块采用的技术

```text
FAST-LIVO2 LIO/VIO 前端
        ↓
保存 LiDAR 关键帧及原始 IMU 位姿
        ↓
距离、时间和关键帧编号筛选回环候选
        ↓
历史局部子图 + 当前关键帧 ICP 配准
        ↓
GTSAM iSAM2 位姿图优化
        ↓
全局优化轨迹与稠密彩色全局地图
```

核心组成如下：

- **关键帧**：按位移、旋转和时间间隔保存代表性 LiDAR 点云，减少回环计算量。
- **候选检索**：只比较时间足够远、编号相差足够大、且按当前轨迹距离接近的历史关键帧。
- **ICP 几何验证**：当前点云与历史关键帧局部子图精配准；仅当 ICP 收敛且 fitness 小于阈值时，才接受回环。
- **GTSAM iSAM2**：将连续里程计边和可信回环边共同优化，使整条轨迹平滑校正，而不是只移动最后一段。
- **map–odom 分离**：FAST-LIVO2 前端始终在连续的 `camera_init`（可视为 `odom`）中定位；优化结果发布在全局 `map` 中，不破坏前端局部体素地图。
- **RGB 重投影**：根据优化前、后的关键帧位姿计算时间插值校正场，将每批已着色点云重投影到全局一致坐标系。

## 3. 代码结构与工作方式

主要新增文件：

```text
include/loop_backend.h
src/loop_backend.cpp
src/loop_optimizer_main.cpp
config/loop_backend_robotdog.yaml

include/dense_rgb_reprojector.h
src/dense_rgb_reprojector.cpp
src/rgb_reprojector_main.cpp
```

模块提供两种使用方式：

1. **离线工具** `fast_livo_loop_optimize`：读取已保存关键帧，适合调参、复核或重新导出。
2. **在线后端**：建图时在后台低频运行；收到 Ctrl-C 后冲刷尾部关键帧、进行最终优化并自动导出最终地图。

在线后端不会覆盖 `_state`、`VoxelMapManager` 或前端 `camera_init` 位姿。它只发布和导出 `map` 坐标系下的优化结果，因此不会因回环而造成前端定位突跳。

## 4. C2 自动全局建图流程

机器狗配置已启用自动稠密 RGB 导出。建图正常结束时，流程为：

```text
Ctrl-C
  ↓
停止后台轮询并冲刷尾部关键帧
  ↓
最终 ICP + iSAM2 优化
  ↓
写入最终优化关键帧位姿
  ↓
等待 RGB 缓存线程写完全部点云批次
  ↓
自动重投影全部 RGB 点（0 m，不降采样）
  ↓
保存 FAST-LIVO2 原始 PCD
  ↓
成功后清理中间文件
```

`auto_export_voxel_leaf_m: 0.0` 表示完全不降采样。最终 PCD 的彩色外观和点密度与 `all_raw_points.pcd` 对应，只是点坐标已应用回环全局校正。

导出时会显示进度，例如：

```text
[dense-rgb] Automatic final export begins: ...
[dense-rgb] Loaded ... RGB batches and ... raw/final keyframe pose pairs.
[dense-rgb] Scanned 500/... RGB batches for output size.
[dense-rgb] Reprojected 500/... RGB batches.
[dense-rgb] Automatic final RGB map export completed: ...
[dense-rgb] C2 cleanup complete.
```

自动 C2 的代码和配置已经完成；首次使用新版本时，应完整回放一次数据，确认上述自动导出和清理日志均出现。

## 5. 最终保留结果

成功后，主要结果统一保存在 `Log/pcd/`：

```text
Log/pcd/all_raw_points.pcd
Log/pcd/all_downsampled_points.pcd
Log/pcd/all_global_optimized_rgb_dense_full.pcd
Log/pcd/optimized_keyframe_poses_imu.txt
```

其中：

- `all_raw_points.pcd`：未做全局回环校正的原始彩色稠密地图，用于对比；
- `all_downsampled_points.pcd`：原 FAST-LIVO2 的轻量下采样预览地图；
- `all_global_optimized_rgb_dense_full.pcd`：最终交付地图，彩色、稠密、不降采样且全局回环校正；
- `optimized_keyframe_poses_imu.txt`：最终优化后的关键帧轨迹。

仅当最终稠密 RGB PCD 和优化轨迹 TXT 均成功写入后，程序才会清理：

```text
Log/dense_rgb_cache_robotdog_c2/     # RGB 批次缓存
Log/pcd/keyframes_robotdog_c2/       # 回环关键帧及原始关键帧位姿
Log/loop_online_final_robotdog_c2/   # 稀疏优化 PCD、回环边 CSV、报告和临时轨迹
Log/pcd/lidar_poses.txt              # 原始未优化轨迹
```

若任一优化或导出步骤失败，清理不会执行，缓存和关键帧会保留，可使用离线工具恢复或调试。

## 6. 验收方法

回环是否真正生效，按以下顺序确认：

1. 控制台出现 `Accepted loop <current> -> <history>`；
2. 最终日志出现 `Optimization complete`，且回环边数量大于零；
3. 查看 `all_global_optimized_rgb_dense_full.pcd` 的首尾重叠区域；
4. 道路、建筑立面不再有明显分层、双层或横向错位；
5. 与 `all_raw_points.pcd` 对比，确认全局对齐改善且局部细节仍保持清晰。

## 7. 后续可选增强

当前完成的是可靠的**激光回环**。后续可以增加视觉地点识别，但应作为候选召回层，而不是替换现有 ICP 和 GTSAM：

```text
历史图像检索 / 视觉地点识别
        ↓
给出可能的历史关键帧
        ↓
现有 LiDAR ICP 精确验证
        ↓
现有 GTSAM 后端优化
```

这样能在长距离漂移较大、距离候选难以找到真实首尾位置时，提高回环候选的召回率，同时保留 LiDAR 的米制几何精度和当前已验证的后端。
